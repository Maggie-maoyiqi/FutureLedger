# 前端选型决策：Vue 3

日期：2026-10-16；状态：正式前端开发基线。此项更新替代先前文档中的 Next.js 前端建议，两份原始参考 DOCX 保持原样。

## 结论与依据

采用 **Vue 3 + TypeScript + Vite + Vue Router + Pinia + ECharts**，使用单文件组件、Composition API 和 `<script setup lang="ts">`。FastAPI、PostgreSQL、Worker、Agent 与受控 Text2SQL 路径保持原设计边界。

FutureLedger 的核心界面是登录后的银行工作台，包含表格、表单、对话、图表和持续任务状态。目前没有明确的公开内容索引、SEO 或服务端渲染需求；业务 API 和权限已由 FastAPI 承担。因此选择独立 Vue SPA，让前端成员集中实现交互，按 API 契约与后端并行协作。

Vue 单文件组件可将一块界面的模板、状态逻辑与样式放在一起。是否更容易上手仍取决于成员经验，当前不假设六人都熟悉 Vue，也不以没有测量过的性能优势作为理由。团队可围绕一种组件风格与类型契约协作。

## 为什么现在调整

仓库当前仅有 `prototype/index.html` 和离线计算工具，没有 Next.js/React 组件、package.json 或已开发的正式 Web 应用。现在改变选型的成本主要是同步文档，适合在分工前确定。

保留 HTML 原型供讨论页面和操作流程；正式开发按 Vue 实施，不在这次选型更新中创建第二套演示实现。当前不能称为“Vue 前端已完成”或“已完成 React 到 Vue 迁移”。

## 实施约定

|事项|约定|
|---|---|
|应用目录|`apps/web/`，由成员 E 负责创建；目前尚不存在|
|页面|Vue Router 对应总览、账单、代扣、未来账本、任务、偏好、评审|
|共享状态|Pinia 管理显示状态、会话及当前计划版本；银行事实以 API 查询为准|
|局部逻辑|composable 封装请求、SSE、图表生命周期，组件卸载清理资源|
|API|所有业务调用 FastAPI；统一类型及错误码，不在前端计算最终权限|
|任务|用 operation_id 关联权威状态，未知结果显示待查证，不提供重复付款捷径|
|金额|API 传整数分；前端格式化展示，不用浮点公式生成授权金额|
|部署|Vite 构建静态资源，配置 SPA 页面回退和 `/api` 代理；SSE 代理关闭缓冲并设置合适超时|
|测试|正式工程创建时锁定兼容依赖；类型检查、构建、关键组件测试及浏览器联调|

不增加 Nuxt 服务端层。若将来出现公开内容页或明确的服务端渲染需求，另写决策记录评估。更换前端不改变数据库、银行适配器、确认验证、受控查询和现金流算法的职责。

## 官方依据

Vue 官方[工具链文档](https://vuejs.org/guide/scaling-up/tooling.html)介绍 Vite 与单文件组件，并推荐新项目使用 Vite；[路由文档](https://vuejs.org/guide/scaling-up/routing.html)与[状态管理文档](https://vuejs.org/guide/scaling-up/state-management.html)说明 Vue Router 和 Pinia 的用途。项目是否采用 SPA 是根据本项目需求作出的工程判断。
