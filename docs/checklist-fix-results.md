# 详细功能清单修复与验证

本次以用户提供的 12 章、92 项详细清单和审计 F1–F10 为依据。

- Demo 支出、净支出、收入正确纳入相应方向的转账，聚合和明细共用方向约束；增加转入合计与转出平均值。正式 C 模块与独立 gold 口径保持原契约。
- 模型调用前拦截聊天凭证、跨用户范围和修改余额请求；前端也阻止凭证进入消息和网络。敏感账本上下文不会发送到模型。
- 修复日期追问、切换问题、商户分组、跨月范围、最近明细、退款明细和缺失转账金额的澄清。
- 聊天规划接入确定性模拟，支持明确的 30/90 天周期、参数追问、情景比较和假设下的最早购买日；前端展示曲线、最低余额、事件及假设。
- 修复笔数金额化、表头、账户名称、中文 CSV；同一授权及类别重复确认返回已完成且不重复扣款。
- 月度原因查询展示上月对比与类别差额，不把相关性写成原因。

验证包括后端完整 C4 质量门禁、前端单元测试及构建、真实 Chromium 端到端检查和独立代码复核。12 项质量门禁全部通过，259 项 Python 测试、10 项前端测试通过，Vue/TypeScript 检查和 Vite 构建通过；Chromium 页面错误为 0。

边界：规划使用披露的固定合成事件和每 30 天重复周期，不是历史预测或真实日历月份；只使用已说明的主账户余额，不执行银行转账。真实外部模型的自然语言准确率未在本轮凭借真实密钥验证。通过这些检查不代表任意输入都没有缺陷。
