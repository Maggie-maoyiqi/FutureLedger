# 六人协作分工

A–F 是待替换的成员代号，不猜测姓名、技能和空闲时间。每模块只有一个合并责任人，验收由搭档交叉审查。

|成员|主责与目录|具体功能与首个交付|输入/输出契约|搭档验收|
|---|---|---|---|---|
|A 银行与数据|`services/mock-bank/`, `db/`, `data/`|账户/收款人/流水/代扣API、银行平衡账本、种子、报价、转账及查证；先做手动500转账|B/C调用Bank adapter；银行结果唯一事实|B查幂等；F对账与复位|
|B 安全与执行|`services/api/execution/`, `services/worker/`|确认/认证、策略、原子额度、Outbox、lease、预约、恢复、审计；先做重复点击和丢回包|接收C的操作提议；返回operation状态；不接受模型授予风险级别|A审账本；F测攻击/并发|
|C Agent与应用API|`services/api/agent/`, `contracts/`|会话、Schema、语义上下文选择、追问、DAG、重规划版本、provider adapter；先做三场景路由和同名追问|输入用户文本；输出待校验计划；调用D读计算、B写流程|D审计划参数；E核交互状态|
|D 账单与现金流|`services/api/analytics/`, `services/api/cashflow/`|语义目录、IntentPlan校验、SQL编译、去重净额、证据、按日模拟/候选搜索；先过210离线题，再实现年度/商户/明细|C给受控计划；返回数值/证据/假设/图表；无银行写权限|A审指标字段；F测数值|
|E 前端与体验|`apps/web/`, `prototype/`|首页/账单/代扣/未来账本/助手/任务/偏好/评审、移动适配、SSE、确认/验证卡；先用固定契约mock并行|消费C API和B权威状态；绝不在浏览器决定权限|C验追问；B审确认/未知状态|
|F 测试与交付|`tests/`, `benchmark/`, `infra/`, `docs/`|数据审计、端到端适配器、故障注入、沙箱隔离、Compose、CI、部署与材料；先建真实结果格式|每模块测试夹具；输出独立报告和演示复现|B审沙箱；全员按README复建|

D承担两种确定性计算，是可并行子任务；C完成意图路由后协助现金流接口。F不独自承担全团队测试：每人提交模块测试，F负责集成、独立验收和证据。B复杂度最高，A协作并发银行契约；禁止把安全全部留到最后。

## 接口先冻结

第1次团队会（建议60–90分钟）：共同评审00共识、03字段/接口、指标口径、上海日期、金额分、订阅查询权限、30天演示时钟及错误码。每人用一条成功与一条失败输入走接口；冻结契约v0.1。变更通过PR更新contract_version及consumer，不能口头改字段。

目录为预定所有权，尚未存在的服务目录不表示已有实现。当前代码只有离线数据/参考计算和原型。

## 四个验收里程碑

|阶段|每人并行工作|必须通过才能推进|
|---|---|---|
|M0 契约与数据|A核schema；B定状态/授权；C定plan；D定指标；E搭页面；F建CI与夹具|字段/枚举/错误码可互相消费；生成数据可复现|
|M1 无LLM银行闭环|A银行；B执行门；C API；D计算器；E确认任务；F并发/恢复测试|500转账、取消代扣、流水对账；无授权不得写；丢回包不重付|
|M2 Agent与未来账本|C接结构化模型；D分析/现金流；E曲线/版本；A/B支持；F接全套评测|三场景独立成功/失败；旧授权失效；两套工资场景可复算|
|M3 安全与交付|F主导全链路及沙箱；每人修模块缺陷、写演示章节|60验收规格真跑、210参考题、独立机器复建、五分钟演示|

先按里程碑排期，未获团队可用时间和截止日期前不承诺具体交付日。每日短同步只报契约变化、阻塞和可验收成果。

## Git协作

main保持可运行，功能分支如`codex/bank-adapter`、`codex/execution-gate`、`codex/agent-planner`、`codex/analytics-cashflow`、`codex/web-workspace`、`codex/benchmark-infra`。每个PR至少1个搭档审查，B/A涉及资金状态的改动由双方交叉审阅。

共享字段由A维护DDL、C维护plan契约；消费者必须参加评审。代码合并说明包含问题、最终行为、验证和未覆盖项。不要提交.env、密钥、真实账单或验证码。许可证需要团队确认后选择，当前不自动为同学设计声明开源许可。
